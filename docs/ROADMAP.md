# 未移植资源与后续建议（ROADMAP.md）

**这份清单回答一个问题：还有什么没做。**

ESP32-S31 是一颗很新的芯片，外设比已移植的多得多。这张表把"硬件有、驱动没有"
的东西列全，并给出优先级判断——**不是所有都值得移植**。

---

## 一、已经做完的（供对照）

内核、双核、Wi-Fi、BLE、以及 13 个外设驱动。
详见 `PERIPHERALS.md`。

---

## 二、未移植：按"值不值得做"排序

### 第一优先级：常见需求，工作量可控

| 外设 | 为什么值得 | 估计工作量 | 参考实现 |
|---|---|---|---|
| **USB OTG（CDC-ACM）** | 多一个串口，也是最简单的 USB 功能 | 中（改 3 处 + 写一个 class） | `docs/USB.md` 有完整步骤 |
| **SD/MMC** | 存储扩展，TF 卡 | 中 | IDF `esp_driver_sdmmc` |
| **I2S** | 音频输入输出 | 中 | IDF `esp_driver_i2s` |
| **温度传感器** | 十来行代码，可做健康监控 | **极小** | `SOC_TEMP_SENSOR_SUPPORTED` |
| **RNG** | 随机数，密码学需要 | 小 | `SOC_RNG_SUPPORTED` |

**建议从这里开始。** 温度传感器和 RNG 是半天的活，
USB CDC 是本包已经铺垫好（能力探针 + 三处明确改动）的下一步。

### 第二优先级：有需求再做

| 外设 | 说明 | 工作量 |
|---|---|---|
| **硬件加密**（AES/SHA/MPI/ECDSA） | 现在走软件 mbedtls，慢但能用 | 大 |
| **ADC DMA / 差分输入** | 高性能采样才需要 | 中 |
| **低功耗 / deep sleep** | 要对接 RT-Thread PM 框架 | 大 |
| **CAN FD** | 现在只有经典 CAN（TWAI） | 中 |
| **SPI 从机** | 现在只做了主机轮询 | 小 |
| **完整 SPI 设备接口** | 现在只有轮询回环，不是 `rt_spi_bus` | 中 |

### 第三优先级：小众或工作量大

| 外设 | 说明 | 工作量 |
|---|---|---|
| **LCD**（I80 / RGB） | `SOC_LCDCAM_SUPPORTED`，含 RGB 并行 | **很大** |
| **Camera** | `SOC_LCDCAM_CAM_SUPPORTED` | 大 |
| **JPEG 编解码** | 依赖 DMA2D | 大 |
| **PPA / DMA2D** | 图形加速 | 大 |
| **Touch** | `SOC_TOUCH_SENSOR_SUPPORTED` v3 | 中 |
| **Ethernet MAC** | 1000M + PTP，工程量大 | **很大** |
| **LP core / ULP** | 超低功耗协处理器 | 大 |
| **ETM**（事件任务矩阵） | 硬件事件联动 | 中 |
| **并行 IO**（PARLIO） | 高速并行接口 | 中 |
| **Bitscrambler** | 特殊用途 | 小 |
| **CORDIC** | 数学加速 | 小 |
| **模拟比较器** | `SOC_ANA_CMPR_SUPPORTED` | 小 |

### 硬件没有的

| 外设 | 证据 |
|---|---|
| **DAC** | `SOC_DAC_SUPPORTED` 未定义 |
| **Wi-Fi 5 GHz** | `SOC_WIFI_SUPPORT_5G` 未定义（S31 是 2.4 GHz Wi-Fi 6） |

## 三、已移植但有缺口

这些**能用**，但接口或功能不完整：

| 项 | 现状 | 缺什么 |
|---|---|---|
| **SPI** | 轮询回环 | 不是 `rt_spi_bus`，没有设备接口 |
| **UART 波特率** | 固定 115200 | `uart_ll.h` 缺 `get_sclk`/`set_sclk`，要直接操作 `HP_SYS_CLKRST` |
| **GPIO 中断** | 只有通道 0 | `gpio_ll_intr_enable_on_core()` 硬编码 `GPIO_LL_INTR0_ENA`（IDF TODO IDF-7995） |
| **USB** | 只有能力探针 | 整个设备/主机栈 |
| **`rt_kprintf`** | 走 ROM putc | 不走设备层（有意为之，见下） |

### 为什么 `rt_kprintf` 故意不走设备层

驱动出问题时控制台仍然可用，否则失去唯一调试通道。
稳定后可以改成走 `rt_serial`，但**不建议在 bring-up 阶段这么做**。

## 四、已知 bug（未修）

| 问题 | 影响 | 为什么没修 |
|---|---|---|
| `bind <运行中的线程> 1` 让线程卡死 | 中 | 变通方法简单（创建时绑核） |
| `console set uart0` 后 shell 输入失效 | 中 | 复位可恢复；不清楚正确语义 |
| `pwm get 0` 打印 `2147483647%` | 低（只是显示） | 上游 `rt_drv_pwm.c` 的除零，改了会偏离上游 |
| `s31twai` 同会话重复跑失败 | 低 | 冷启动正常；原因未查明 |
| `ADC` 只支持单次转换 | 低 | DMA 未接 |

## 五、如果你要接手，建议的顺序

1. **先跑通**：`docs/RELEASE-CHECK.md` 记录了验证方法
2. **读 `docs/PORTING.md`**：理解结构，特别是 §8 的 `--gc-sections` 坑
3. **读 `docs/SMP.md` §4–§6**：双核的三个坑，这些是最容易重蹈的
4. **挑一个第一优先级的外设**：建议温度传感器（最简单，建立信心）
5. **每做一步，跑 `s31test`**：确认没破坏已有功能
6. **把你的发现追加到 `docs/porting-log.md`**：**包括失败的尝试**

## 六、这个移植的方法学（比代码更重要）

如果只记一件事，记这个：

**"间歇性通过不算通过"、"每个检查器都必须能失败"、
"负结果要写进代码注释而不是只写进聊天记录"、"done ≠ useful"。**

具体展开：

| 原则 | 意思 |
|---|---|
| **间歇通过不算通过** | 至少连跑 3 次，或者找出间歇的原因 |
| **检查器必须能失败** | 加一条检查时先故意破坏对应条件，确认它报错，再恢复 |
| **不能失败的检查器比没有更糟** | 它给人虚假的安全感 |
| **不要为了吸收噪声而放宽测量窗口** | 那是在隐藏问题 |
| **负结果要记进注释** | 只写在聊天里的结论会丢 |
| **"做完了" ≠ "有用了"** | 代码能编译不代表功能对 |
| **panic 的 `MEPC` 比错误文本有用** | 用 `addr2line` 解出来 |
| **关掉一个变量做对照，比加十个探针快** | 二分法优先于观察法 |

## 七、一句话

**内核和常用外设是完整可用的；USB、音频、存储、显示是明确的下一个战场；
每一个未移植项都有明确的原因和参考实现。**
